ODI Demo Builder — Session Guide

Both of you run this simultaneously  ·  One person shares screen on the Meet so you both see results  ·  ~3 hours  ·  No skill install required — paste prompts directly into Claude Code
How this works. Each phase has a prompt in a red-bordered box. Both of you paste it into your own Claude Code session at the same time. One of you shares your screen so you can compare what Claude Code produces and talk through it. When Claude Code asks a question, answer it together. When something breaks, tell Claude Code exactly what happened and ask it to fix the issue — that is the right approach for every error you hit in this session.

Before you start 5 minutes

Both of you — run this verification block before touching Claude Code. Every line should return output, not an error. 
claude whoami
op whoami
aws sts get-caller-identity --query Account --output text
echo "Fivetran key: ${FIVETRAN_API_KEY:0:8}..."
echo "Fivetran secret: ${FIVETRAN_API_SECRET:0:8}..."
If anything fails, paste the error into the Meet chat and ask Claude Code: "This command failed — how do I fix it?" Claude Code will give you the exact steps.
One of you — share your screen on the Meet now. The person who shares screen is the reference point. When your outputs differ, the shared screen is what you discuss. Either person can share; just pick one and keep it consistent through the session.
Both of you — agree on these before pasting any phase prompt:
  1. Industry vertical and fictional company name — the name must not be a real company. Claude Code will validate it.
  2. Buyer persona — CDO, CIO, or Head of Data Engineering. This shapes the frontend copy.
  3. The exact 1Password item name for the SQL Server credentials — Claude Code will use op read to fetch host, port, username, password from it.
When something breaks, do this: Paste the full error output into Claude Code and say "this failed — what is the fix?" Do not try to solve errors by editing files or commands yourself before asking Claude Code. Claude Code has full context of what it built and can diagnose faster than manual investigation. This is true for every error in every phase.

Phase 1 — Gather target: 15 minutes

PHASE 1 — GATHER

Claude Code collects the demo context, pulls SQL Server credentials from 1Password, tests connectivity, lists tables, and gets your update-method decision.

You are facilitating a hands-on Fivetran ODI demo build session. Your job is to guide the build of a production-ready ODI demo from scratch — SQL Server as the source, Fivetran as the ingest layer, Apache Iceberg on S3 as the lake, dbt for bronze/silver/gold transforms, and a React frontend as the demo surface. Narrate your reasoning at every decision point. Start by collecting five inputs: 1. Industry vertical and fictional company name — validate that the name does not collide with a real entity before proceeding 2. Buyer persona: CDO, CIO, or Head of Data Engineering 3. The 1Password item name for SQL Server credentials — you will fetch host, port, username, and password using op read 4. AWS region (default us-east-1) and S3 bucket name prefix 5. Target database and table selection — list these after connectivity is confirmed Ask for all five now. Do not start any infrastructure work until you have them.

Answer Claude Code's questions. When it asks for the 1Password item name, give it the exact name from your vault. Claude Code will run op read to pull credentials — nothing gets pasted in plaintext.

When Claude Code asks about the update method, it will present two options: CDC (log-based, requires SQL Server Agent and VIEW SERVER STATE permission) and full reload. Choose the one that fits the SQL Server environment you are working with. Claude Code will confirm what it needs from the server for whichever you pick.
Phase 1 done when: connectivity confirmed, tables selected, update method decided.

When something breaks — how to handle it

This applies to every phase. The same approach works every time:

  1. Do not try to fix the error by editing files or rerunning commands yourself first.
  2. Copy the full error output — the complete text, not just the last line.
  3. Paste it into Claude Code and say: "This failed. Here is the error. What is the fix?"
  4. Claude Code will diagnose it and give you the exact corrective steps.

Common situations and what they usually mean:

What you seeWhat to paste to Claude Code
op read returns nothingThe full terminal output plus: "op read returned empty, here is what I got"
SQL Server port not reachableThe nc or sqlcmd output plus: "connectivity check failed, this is the result"
Terraform plan has unexpected resourcesThe full plan output plus: "I see resources I did not expect, please explain"
Fivetran API returns an error codeThe full API response JSON plus: "the API returned an error"
dbt build failsThe full dbt output including the error block plus: "dbt build failed"
Athena query failsThe full error message plus: "Athena returned this error"

Hybrid deployment — the data-residency answer

Claude Code will surface this during Phase 2 as a short aside. It is the answer to the customer objection "we cannot send our data to a third-party cloud."

Fivetran Hybrid Deployment runs the data-movement agent inside the customer's own network. Fivetran's cloud plane receives only orchestration metadata — row counts, schema, sync timestamps. No customer data transits Fivetran's infrastructure.

What stays identical: the connector configuration, the MDLS destination, the dbt pipeline, the React frontend. Hybrid deployment is a deployment mode applied in front of the same architecture you built today.
