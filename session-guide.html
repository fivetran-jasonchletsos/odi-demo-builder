Troubleshooting

  • op read returns empty: Run op signin in a terminal tab, then tell Claude Code "1Password is signed in now, retry the credentials step."
  • SQL Server not reachable: Check VPN first. If the server is in a private subnet, tell Claude Code — it will explain the Hybrid deployment option, which is the real-world customer answer to this situation.
  • Terraform IAM role fails: The fivetran_aws_account_id in tfvars must match exactly what the Fivetran MDLS destination setup screen shows. Update tfvars and re-run.
  • Fivetran API 401: FIVETRAN_API_KEY and FIVETRAN_API_SECRET must be set as separate env vars. Run echo $FIVETRAN_API_KEY — if blank, export them and retry.
  • dbt "database not found": The database: in profiles.yml must be awsdatacatalog, not the Glue database name. The Glue database name goes in the schema field of sources.yml.
  • CDC sync stuck in SYNCING: SQL Server Agent must be running and the sync user needs VIEW SERVER STATE permission. Tell Claude Code — it will give you the exact SQL to verify both.

Hybrid deployment talking points

Claude Code will surface these during Phase 2. Andy, this is the HVR replacement pitch for your banking and healthcare customers.

The objection: "We cannot send patient data / transaction records / PII to a third-party cloud."

The answer: Fivetran Hybrid Deployment runs the data-movement agent inside the customer's own network. Fivetran's cloud plane receives only orchestration signals and metadata — row counts, schema, sync timestamps. No customer data transits Fivetran's cloud infrastructure.

What stays identical: The connector config you set up today. The MDLS destination. The dbt pipeline. The React frontend. Hybrid deployment is a deployment mode, not a different architecture.

The pitch: "This is the HVR story with a managed control plane. You get log-based CDC without standing up and operating HVR yourself. Data stays in your network. Fivetran handles scheduling, schema drift detection, and delivery to your Iceberg lake."
