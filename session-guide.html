ODI Demo Builder — Session Guide

Both of you run this simultaneously  ·  One person shares screen on the Meet so you both see results  ·  ~3 hours  ·  No skill install required — paste prompts directly into Claude Code
How this works. Each phase has a prompt in a red-bordered box. Both of you paste it into your own Claude Code session at the same time. One of you shares your screen so you can compare outputs and talk through it. When Claude Code asks a question, the screen-sharer answers; the other person types the same answer into their own session. When something breaks, tell Claude Code exactly what happened and ask it to fix the issue — that is the right approach for every error in this session. Keep the same Claude Code session open for all four phases. Do not close or restart it between phases — the later prompts rely on context from earlier ones.

Before you start 5 minutes

Both of you — open a terminal in the directory where you want the demo project created. Run claude from there. Every file Claude Code generates lands relative to that directory. Keep that terminal open for the full session.
Both of you — sign in to 1Password first. Running op signin directly will print an error telling you to use eval instead — that is expected. The correct command is: 
eval $(op signin)
Enter your 1Password credentials when prompted. Then run the full verification block — every command should return output, not an error. 
claude whoami
op whoami
terraform version
dbt --version
node --version
npm --version
jq --version
aws sts get-caller-identity --query Account --output text
echo "Fivetran key: ${FIVETRAN_API_KEY:0:8}..."
echo "Fivetran secret: ${FIVETRAN_API_SECRET:0:8}..."
If anything fails, paste the error into Claude Code: "This command failed — how do I fix it?"
One of you — share your screen on the Meet now. Keep the same person sharing for the full session. When your outputs differ, the shared screen is the reference.
Both of you — agree on these three things before pasting any prompt. Write them down or paste into the Meet chat so you both have them.
  1. Industry vertical and fictional company name. The name must not be a real company. Examples that work: Aldermoor Systems, Crestfield Analytics, Vantage Meridian. Claude Code will validate your choice.
  2. Buyer persona — CDO, CIO, or Head of Data Engineering. This shapes the frontend copy.
  3. Your 1Password vault name and item name for the SQL Server credentials. Claude Code will use these to construct op://vault/item/field URIs — you need both the vault name and the item name, not just the item name.
When something breaks, do this every time:
  1. Do not try to fix the error by editing files or rerunning commands yourself first.
  2. Copy the full error output — the complete text, not just the last line.
  3. Paste it into Claude Code and say: "This failed. Here is the error. What is the fix?"
  4. Claude Code will diagnose it and give you the exact steps.
If Claude Code cannot resolve the error within 15 minutes, the issue is likely outside your control (firewall, missing IAM permissions, disabled CDC on the SQL Server). Pause and escalate to whoever administers that system before continuing.

Phase 1 — Gather target: 15 minutes

PHASE 1 — GATHER

Claude Code collects the demo context, pulls SQL Server credentials from 1Password, tests connectivity, lists tables, and gets your update-method decision.

You are facilitating a hands-on Fivetran ODI demo build session. Your job is to guide the build of a production-ready ODI demo from scratch — SQL Server as the source, Fivetran as the ingest layer, Apache Iceberg on S3 as the lake, dbt for bronze/silver/gold transforms, and a React frontend as the demo surface. Narrate your reasoning at every decision point. Start by collecting five inputs: 1. Industry vertical and fictional company name — validate that the name does not collide with a real entity before proceeding. Check your training knowledge for any registered business, publicly traded company, or well-known brand with that exact name. Reject it if you find any match. 2. Buyer persona: CDO, CIO, or Head of Data Engineering 3. The 1Password vault name AND item name for SQL Server credentials — ask for both separately. Construct four op read URIs in the format op://vault-name/item-name/field-name for host, port, username, and password (standard 1Password field names are "server", "port", "username", "password"). Run each as: export FIELD=$(op read "op://vault-name/item-name/field-name"). Never prompt for credentials in plaintext. 4. AWS region (default us-east-1) and S3 bucket name prefix 5. Target database and table selection — list these after connectivity is confirmed Ask for all five now. Do not start any infrastructure work until you have them.

Answer Claude Code's questions. For 1Password, give both your vault name and item name when asked — it will construct the op:// URIs itself.

When Claude Code asks about the update method, it will present three options: XACT (transaction-based log reading, no SQL Server Agent required — recommended), LOG_BASED (uses SQL Server replication, more setup required), or RELOAD (full table scan, no special permissions). If you do not administer the SQL Server and cannot confirm CDC is enabled, choose RELOAD — you can change it in the Fivetran dashboard later. To verify CDC readiness before choosing XACT, run on the SQL Server: SELECT name, is_cdc_enabled FROM sys.databases WHERE name = 'your_db'.
Phase 1 done when: connectivity confirmed, tables selected, update method decided.
Keep this Claude Code session open. Do not close or restart it. Phase 2, 3, and 4 all reference values Claude Code collected here. If you restart, paste the Phase 1 prompt again and re-answer the questions before continuing.

When something breaks — how to handle it

The same approach works for every error in every phase:

  1. Do not try to fix the error by editing files or rerunning commands yourself first.
  2. Copy the full error output — the complete text, not just the last line.
  3. Paste it into Claude Code and say: "This failed. Here is the error. What is the fix?"
  4. Claude Code will diagnose it and give you the exact steps.
What you seeWhat to paste to Claude Code
op read returns nothingFull terminal output + "op read returned empty — my vault name is X and item name is Y"
SQL Server port not reachableFull nc or sqlcmd output + "connectivity check failed"
Terraform plan has unexpected resourcesFull plan output + "I see resources I did not expect, please explain"
Fivetran API returns an error codeFull API response JSON + "the API returned an error"
dbt compile or build failsFull dbt output including the error block + "dbt failed"
Athena query failsFull error message + "Athena returned this error"
sync_poll.sh exits with "failed"The sync_state value + the Fivetran connector status JSON + "sync failed"

If Claude Code cannot resolve the error within 15 minutes, the issue is likely outside your control — firewall blocking the SQL Server port, missing IAM permissions on a locked-down account, or CDC not enabled on the source database. Pause the session and escalate to whoever administers that system before continuing.

Hybrid deployment — the data-residency answer

Claude Code delivers this during Phase 2 as a short aside. It is also here for reference if a customer raises a data-residency concern during the demo.

Fivetran Hybrid Deployment runs the data-movement agent inside the customer's own network. Fivetran's cloud plane receives only orchestration metadata — row counts, schema, sync timestamps. No customer data transits Fivetran's infrastructure.

What stays identical to what you built today: the connector configuration, the MDLS destination, the dbt pipeline, the React frontend. Hybrid deployment is a deployment mode, not a different architecture.
